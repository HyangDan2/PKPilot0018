## 1. 무엇을 푸는가

## 2. 개별 만족도 (Derringer–Suich Desirability)

각 반응의 예측값 ŷ를 0~1의 숫자로 바꾼다. 0은 받아들일 수 없음, 1은 정한 한계 안에서 가장 좋음이다. 반응마다 단위가 달라도 이 척도 위에서는 비교할 수 있다.

| 목표 | 한계의 의미 | d(ŷ) |
| --- | --- | --- |
| Maximize | `Lower` = 받아들일 수 없는 아래쪽, `Upper` = 이상점 | ŷ ≤ L → 0, ŷ ≥ U → 1, 그 사이 `((ŷ−L)/(U−L))^w` |
| Minimize | `Lower` = 이상점, `Upper` = 받아들일 수 없는 위쪽 | ŷ ≤ L → 1, ŷ ≥ U → 0, 그 사이 `((U−ŷ)/(U−L))^w` |
| Target | `Target` = 가장 좋은 값, `Lower`/`Upper` = 한계 | 목표에서 1, 한계에서 0. ŷ ≤ T: `((ŷ−L)/(T−L))^w`, ŷ > T: `((U−ŷ)/(U−T))^w` |
| In range | `Lower`~`Upper`가 합격 구간 | 구간 안 1, 밖 0 (계단) |
| Ignore | — | 1 (계산에서 제외, 예측·보고는 유지) |

`w`가 **Weight**다. 곡선 하나의 모양만 바꾼다. `w=1`이면 선형, `w>1`은 좋은 쪽 끝에 가까울수록 급격히 오르고(반대로 나쁜 쪽에서 천천히), `w<1`은 나쁜 쪽을 빨리 벗어난다.

### Weight와 Importance는 다른 값이다

- **Weight**(0.1~10, 반응별): 그 반응의 만족도 곡선을 휜다. **다른 반응과의 상대 비중은 바꾸지 않는다.**
- **Importance**(0.1~10, 반응별): 종합 만족도에서 그 반응이 차지하는 몫을 바꾼다(§3).

두 값을 하나로 합치면 "곡선이 급하다"와 "이 반응이 더 중요하다"가 구별되지 않으므로 분리했다. UI에서도 다른 열이다.

### 규격 만족 여부는 한계에 대해 판정한다

만족도는 "얼마나 좋은가"이고, 규격 판정(`compliant`)은 "받아들일 수 있는가"다. 목표에 따라 한계의 의미가 다르므로 판정도 목표별로 한다.

- Maximize: ŷ ≥ Lower (Upper를 넘어도 합격 — 그쪽은 이상점이다)
- Minimize: ŷ ≤ Upper
- Target / In range: Lower ≤ ŷ ≤ Upper

### 정의할 수 없는 입력은 지어내지 않는다

한계가 없거나(`lower`/`upper` 결측), 두 한계가 같거나, `Target`이 한계 밖이거나, `Weight`가 0 이하이면 그 반응은 **문제 목록에 이유를 적고 계산에서 빠진다**. 어떤 반응도 참여할 수 없으면 최적화 자체를 `invalid`로 끝내고 이유를 보여준다.

## 3. 종합 만족도 (Composite Desirability)

참여하는 반응들의 만족도를 **중요도 가중 기하평균**으로 합친다.

```
D = ( Π dᵢ^Iᵢ ) ^ (1 / Σ Iᵢ)        (Iᵢ = Importance, 참여 반응만)
```

- **기하평균**인 이유: 한 반응이라도 d=0이면 D=0이다. "모든 반응이 규격 안"이라는 요구를 산술평균처럼 희석하지 않는다.
- **중요도**가 다르면 같은 상대 손실이라도 더 중요한 반응이 D를 더 크게 움직인다. `I=2`는 `I=1`의 두 배다.
- 참여 반응이 하나도 없으면(모두 Ignore) D=0 — 만족시킬 목표가 없기 때문이다.

## 4. 탐색 엔진

만족도 함수는 계수의 2차식이므로 매끄럽지만, 여러 반응의 곱·거듭제곱·계단(범위 내)이 섞이면 국소 최적점이 생길 수 있다. 그래서 네 가지 방법을 두고, 방법마다 **무엇을 보장하는지**를 다르게 표시한다.

| 방법 | 하는 일 | 보장 |
| --- | --- | --- |
| Grid Search | 연속 인자를 격자로 훑고, 이산은 간격대로, 범주는 수준마다 | 격자 위 최선. 전역 최적은 주장하지 않음 |
| Multi-start Local Search | 격자로 좋은 골짜기를 찾은 뒤, 시드로 뽑은 여러 시작점에서 좌표 패턴 탐색(이동 → 실패 시 간격 반감) | 같은 시드 = 같은 답. 수렴하면 `optimal`, 아니면 `best-found` |
| Bounded Optimization | 한 시작점(중심 또는 최선 격자점)에서 경계를 지키며 같은 정련 | 경계를 벗어나지 않음 |
| Discrete / Categorical Enumeration | 전 조합을 빠짐없이 평가 | 그 공간의 최적 (유일하게 "전역"을 주장할 수 있는 방법) |

- **격자점 수**: 연속 인자 축마다 `gridPoints`(기본 21). 이산 인자는 `step`을 지킨다 — 간격은 사용자가 정한 약속이므로 임의로 줄이지 않는다.
- **탐색 횟수 상한**: `maxEvaluations`(기본 60 000). 격자가 상한보다 크면 연속 축을 반씩 성기게 조정하고 그 사실을 `opt.warn.gridReduced`로 알린다. 이산 축은 그대로 두므로 전수 열거가 상한을 넘으면 `limit` 상태로 끝나고 **그때까지의 최선**을 보고한다.
- **시간 상한**: `timeLimitMs`(기본 4 000 ms). 초과하면 같은 방식으로 `limit`.
- **재현성**: 시작점은 `mulberry32(seed)`로 만들고, 이산/범주 열거와 격자는 결정적이다. 같은 시드·같은 설정이면 평가 횟수까지 같다(테스트가 확인).

### 상태 표시

| 상태 | 뜻 |
| --- | --- |
| `optimal` | 만족 해를 찾았고, 전수 열거이거나 국소 탐색이 허용오차까지 수렴했다 |
| `best-found` | 만족 해를 찾았지만 전역 최적은 주장하지 않는다 (격자, 수렴 전 종료) |
| `no-feasible` | 어떤 조건도 모든 목표를 만족하지 못했다 (종합 만족도 0) |
| `invalid` | 문제 정의가 성립하지 않는다 (반응 없음, 전 인자 고정, 범위 오류, 랭크 부족 모형) |
| `limit` | 평가/시간 상한에 걸렸다. 최선의 해는 함께 보고한다 |

## 5. 예측과 구간

각 후보 조건에서 반응별로 다음을 계산한다.

- **적합값** ŷ = x′β (설계행렬은 모형의 코딩 규칙을 그대로 따른다: coded/actual, 범주 대비 +1/−1)
- **표준오차** SE = √(x′Σx), Σ는 저장된 계수 공분산(mse·(X′X)⁻¹)
- **평균 신뢰구간** ŷ ± t₁₋α/₂,df · SE
- **개별 예측구간** ŷ ± t₁₋α/₂,df · √(SE² + mse)

공분산이나 잔차 자유도가 없는 모형(예: 초기 RSM 페이로드)은 SE·구간을 `—`로 두고 값을 지어내지 않는다. UI는 그 사실을 표에서 바로 보여준다.

### 랭크 부족 모형은 최적화 대상이 아니다

식별되지 않은 항(aliased)이 있는 모형은 x=0처럼 그 항의 가중치가 0인 점에서만 그럴듯한 값이 나온다. 그 값은 모형의 성질이 아니라 해법의 인공물이므로, 그런 모형이 하나라도 섞이면 탐색을 시작하지 않고 `invalid` + `opt.issue.nonEstimable`로 끝낸다.

### 외삽 경고

최적 조건의 인자값이 그 모형을 적합한 범위(`factorBounds`) 밖이면 `extrapolated`로 표시한다. 해가 적합 영역 밖에 있다는 것은 "이 조건은 데이터가 지지하지 않는 곳"이라는 뜻이며, 값 자체는 계산되지만 그렇게 표시된다.

### 기본 한계값

- 설계 실험(DOE/RSM) 모형은 저장된 실험점의 관측 반응 범위를 초기 `Lower`/`Upper`로 쓴다.
- 회귀 모형은 실험점을 저장하지 않으므로, **탐색 공간 위의 예측 범위**(각 축 5점 격자)를 초기값으로 쓴다. 이 값은 데이터가 아니라 출발점이며, UI에서 사용자가 언제든 바꾼다. 한계는 값이 아니라 **사용자가 정하는 규격**이므로 "관측값"으로 표기하지 않는다.

## 6. 예측 프로파일러 (WO-06)

인자 하나를 움직였을 때 모든 반응이 어떻게 변하는지를 (반응 × 인자) 행렬로 보여준다.

- **조건부 곡선**: 한 칸의 곡선은 그 인자만 축으로 삼고 **나머지 인자는 모두 현재 값에 고정**한 단면이다. 주변화하거나 평균하지 않는다. 어떤 인자를 움직여도 다른 인자의 현재 값은 유지되며, 다른 인자의 곡선은 새 값 위에서 다시 계산된다(곡선이 서로 일관된다).
- **현재 값 수직선**, **규격선(점선)·목표값(점선)**, **평균 신뢰구간·개별 예측구간 밴드**(모형이 지원할 때만), **개별·종합 만족도**, 규격 만족 배지.
- **Optimize**는 같은 목적함수를 그 자리에서 다시 최적화해 슬라이더를 최적 조건으로 옮긴다. **Reset**은 각 범위의 중심(범주는 첫 수준)으로 되돌린다. **조건 저장**은 현재 조건과 예측표를 출력 카드로 남긴다.
- **입력 지연**: 슬라이더 입력은 40 ms 디바운스 후 반영한다. 드래그 중간값마다 모든 곡선을 다시 그리지 않으면서, 손을 떼면 즉시 최신 값이 보인다. 모형은 한 번만 컴파일(계수 라벨 1회 파싱)해 재사용한다.

허용오차는 결과를 본 뒤 고르지 않았다. `optimizer_objective`(1e-6), `optimizer_argmax`(0.005), `optimizer_prediction`(1e-3), `optimizer_coarse_grid`(2e-3) 각각에 수치적 이유를 `qa/tolerances.json`에 적었다.

### 주장하지 않는 것

- **Minitab과 같은 숫자라는 주장은 하지 않는다.** Minitab의 Response Optimizer는 자체 기본값(가중 1, 중요도 1, 한계 설정 방식)과 자체 최적화기를 쓰므로, 같은 모형·같은 한계·같은 가중을 넣었을 때 결과가 일치하는지는 이 저장소에서 검증되지 않았다. 여기서 검증한 것은 **문서화된 Derringer–Suich 정의와 SciPy 기준 최적화**다.
- **전역 최적 보장**: 격자·다중 시작 탐색은 전역 최적을 보장하지 않는다. 그럴 때 UI는 `best-found`라고 쓴다. 전수 열거만이 그 공간에서 "최적"을 주장한다.
- **평평한 최적점의 유일성**: 목표값 목표나 상한에 붙은 최대화는 같은 만족도를 주는 영역이 넓다. 그때 인자값은 유일하지 않으며, 표시되는 조건은 그 영역의 한 점이다.
